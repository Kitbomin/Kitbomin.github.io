시연 영상

학술제 출품용 84초 시연. 가상 대본(영희·철수)을 두 사람이 읽은 녹음을 대시보드에 올려 Trello 카드 4개가 만들어지는 과정.

실행 결과 다시 보기

아래는 브라우저에서 모델을 돌리는 것이 아니라, 같은 녹음을 run_pipeline.py로 실제 처리한 결과(JSON)를 음성과 맞춰 재생합니다. 발화나 업무 카드를 누르면 해당 위치로 이동합니다.

    파이프라인 구조

    1. 음성 입력wav · mp3 · m4a · mp4
      Streamlit 대시보드 / FastAPI
    2. 음성인식WhisperX medium
      강제 정렬로 단어 타임스탬프
    3. 화자분리pyannote.audio 3.1
      단어 단위 화자 할당
    4. 업무 추출Ollama · Llama 3.1 8B
      temperature 0, JSON 출력
    5. Trello 등록업무 항목만 외부 전송
      담당자·기한은 설명란

    1 – 4단계는 모두 로컬 PC(RTX 4060 Laptop)에서 실행됩니다. 회의 내용을 외부 API로 보내기 어려운 조직을 가정한 구성입니다.

    성능 평가

    한국어 대화 음성 3개(총 74.1초)의 정답 전사문을 표준 표기로 정규화한 뒤 측정한 예비 평가입니다.

    25.45%WER · 어절 (정규화 전 31.43%)
    12.88%CER · 음절
    21.82%sWER · 띄어쓰기 정규화

    확인된 한계

    • 인명 오인식이 담당자 필드로 전파 — 남은 오류는 대부분 인명·유사 발음 어휘의 치환.
    • 맞장구가 많은 대화에서 화자 병합 — 짧은 "네"가 반복되면 두 화자가 하나로 합쳐짐.
    • 평가 표본이 작고, 업무 추출 정확도는 정량 평가하지 않음.

    대응

    • 담당자를 화자 ID가 아니라 발화 속 이름·호칭에서 뽑도록 프롬프트 설계 → 화자분리가 실패해도 담당자는 유지.
    • "회의 내용에 없는 정보는 지어내지 마", 담당자·기한이 없으면 null → 환각 억제.
    • 정규화 전/후 WER을 함께 보고해 정답 전사문의 표기 차이와 실제 오류를 분리.

    트러블슈팅 · 보수 기록

    API 경로에서 Trello 카드가 항상 0개

    원인 업무 추출 함수가 이미 list를 반환하는데 라우터에서 다시 json.loads()를 호출 → TypeError가 bare except에 묻혀 빈 리스트로 처리.

    해결 이중 파싱 제거, 파싱 책임을 서비스 한 곳으로 모으고 send_to_trello 옵션 추가.

    LLM 응답이 JSON이 아닐 때 업무 유실

    원인 모델이 ```json 코드블록이나 설명 문장을 붙이면 json.loads 실패.

    해결 코드블록 제거 → 첫 [~마지막 ] 재시도 → dict 항목만 채택. 단위 테스트 5종.

    요청마다 화자분리 모델 재로딩

    원인 정렬·화자분리 파이프라인을 함수 안에서 매번 생성.

    해결 언어별 정렬 모델과 화자분리 모델을 지연 로딩 후 캐시.

    업로드 파일명 경로 조작 · 개인 음성 노출

    원인 클라이언트 파일명을 그대로 저장 경로로 사용, 테스트 녹음이 저장소에 커밋됨.

    해결 확장자 화이트리스트 + UUID 파일명, 음성·정답 전사문을 .gitignore 처리하고 시연은 가상 대본만 사용.
